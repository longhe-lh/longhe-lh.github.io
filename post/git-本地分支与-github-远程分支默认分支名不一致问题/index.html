Git 本地分支与 GitHub 远程分支默认分支名不一致问题

问题描述

  • GitHub 新建仓库时，默认主分支是 main。
  • 本地通过传统 git init 初始化仓库时，默认分支通常是 master。
  • 导致本地分支与远程仓库默认分支名称不一致，容易产生混淆和同步问题。

具体表现

  • 本地推送命令使用 git push -u origin master。
  • 远程仓库默认分支是 main，推送后远程仓库会出现两个分支：main 和 master。
  • 远程默认分支仍为 main，本地 master 分支和远程 main 分支无法自动同步。
  • 使用 GitHub 网页界面默认分支（main）时，本地无法跟进更改。

解决方案

方案一：将本地默认分支改为 main

  1. 重命名本地分支：

    1

    git branch -M main

  2. 推送 main 分支并建立追踪关系：

    1

    git push -u origin main

  3. 以后推送和拉取都可以只用：

    1
2

    git push
git pull

方案二：修改 GitHub 仓库默认分支为 master（不推荐）

  • 在 GitHub 仓库的 Settings > Branches 中修改默认分支为 master。
  • 适用于已有大量 master 分支使用习惯的项目。
  • 不推荐，因为社区和 GitHub 趋势是采用 main 作为默认分支。

方案三：设置 Git 全局默认分支为 main（针对新仓库）

1

git config --global init.defaultBranch main
  • 以后用 git init 新建仓库时默认分支会是 main。
  • 避免未来出现分支名不一致的问题。
